== Overview

This document lists the PLC ports and MQTT measurement topics for each station.
`$plcId` and `$machineId` stand for the configured PLC ID and the machine instance ID.
For example, the conveyor feed sensor of `ConveyorBelt01` on `LocalDevPLC` is published at `PLC/LocalDevPLC/ConveyorBelt/ConveyorBelt01/measurements/input/conveyorSensFeed`.
The machine type and status key are case-sensitive.

Each measurement has its own topic under `PLC/$plcId/$machineType/$machineId/measurements/$statusKind/$statusKey`.
`$statusKind` is `input`, `output`, or `internal`. When a status group changes, its measurements are published with QoS 2 and message retention.
The payload has this form:

[source,json]
----
{
  "value": true,
  "timestamp": "2026-09-25T12:00:00+00:00Z"
}
----

`value` is a Boolean, integer, or string according to the measurement.
The timestamp is generated in UTC and includes both the `+00:00` offset and a trailing `Z`.
These topics report measurements and actuator state.
Commands can not be send through MQTT, as `output` topics do not accept MQTT commands.

`I`, `A`, and `B` denote PLC inputs, `Q` denotes a PLC output, and `Virtual` denotes a derived value.
`input` and `output` in MQTT paths are from the PLC's perspective.
`—` means that no MQTT measurement topic is available for that port.
Individual encoder impulse channels have no measurement topic and their aggregate counters appear as `Virtual` values.
